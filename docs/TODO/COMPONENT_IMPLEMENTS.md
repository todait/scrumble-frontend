## 프로젝트 개요

React와 Tailwind CSS를 사용하여 투두리스트 관리 컴포넌트를 구현합니다. 어제 투두에서 선택한 항목들을 오늘 투두로 가져오는 기능과 드래그앤드롭, 다중 선택, Depth 관리 등의 고급 기능을 포함합니다.

## 데이터 구조 정의

### Todo 인터페이스

- id: 고유 식별자 (string)
- text: 투두 내용 (string)
- completedAt: 완료 시간 (Date 또는 null)
- depth: 계층 레벨 (0, 1, 2 중 하나)
- date: 투두 생성 날짜 (Date)
- order: 표시 순서를 위한 숫자값 (number)
- parentId: depth가 1 이상일 때 부모 Todo의 id (선택적 string)

### TodoList 컴포넌트 Props

- todos: Todo 배열
- isEditable: 수정 가능 여부 (본인 투두인지)
- mode: 'view' 또는 'edit' 모드
- onUpdate: todos 업데이트 콜백 함수
- onToggleComplete: 완료 토글 콜백 함수
- selectedIds: 선택된 투두 ID 배열 (어제 투두 선택용)
- onSelectionChange: 선택 변경 콜백 함수

## 컴포넌트 구조

### TodoContainer

전체 투두 시스템의 메인 컨테이너로 어제와 오늘의 투두를 관리합니다.

**주요 기능:**

- 어제/오늘 투두 상태 관리
- 보기/수정 모드 전환 (상단 버튼)
- 선택된 어제 투두를 오늘로 가져오기
- 저장 기능

**상태 관리 항목:**

- yesterdayTodos: 어제 투두 목록
- todayTodos: 오늘 투두 목록
- selectedYesterdayIds: 선택된 어제 투두 ID들
- mode: 현재 보기/수정 모드
- editingTodoId: 현재 편집 중인 투두 ID
- isCollapsed: 접힘 상태 (CollapseTodoListSection용)

### CollapseTodoListSection

접을 수 있는 투두 리스트 섹션으로, 컨텍스트에 따라 다르게 동작합니다.

**동작 방식:**

- 어제 투두 작성 화면: 기본적으로 펼쳐진 상태
- 피드에서 볼 때: 오늘 날짜로 접혀진 상태
- 헤더 클릭으로 펼침/접기 토글

**헤더 텍스트 동적 표시:**

- 선택 0개: "어제의 투두에서 · 투두 0개 선택"
- 미완료만 선택: "미완료 N개 · 가져오기"
- 완료만 선택: "완료 N개 · 가져오기"
- 혼합 선택: "투두 N개 · 가져오기"

**선택 기능:**

- 각 투두 항목 왼쪽에 체크박스 표시
- 다중 선택 가능
- 선택 상태는 보라색으로 표시

### TodoList

재사용 가능한 투두 리스트 컴포넌트로 보기/수정 모드를 지원합니다.

**보기 모드 기능:**

- 체크박스로 완료/미완료 토글 (isEditable true일 때만 - 비지니스 로직에서 자기 자신이 아닐때는 체크안됨.)
- 완료된 항목은 취소선 표시
- 드래그앤드롭 비활성화

**수정 모드 기능:**

- 드래그앤드롭으로 순서 변경
- 같은 리스트 내에서만 이동 가능
- Depth가 있는 항목 드래그 시 하위 항목도 함께 이동
- 드래그 핸들 표시 (세로 점 6개 아이콘)

### TodoItem

개별 투두 항목을 표시하는 컴포넌트입니다.

**구성 요소:**

- 드래그 핸들 (수정 모드에서만 표시)
- 체크박스 (완료 상태 표시/변경)
- 텍스트 영역 (일반 또는 편집 가능한 입력 필드)
- Depth에 따른 들여쓰기

**Depth 표시:**

- depth 0: 들여쓰기 없음
- depth 1: 왼쪽 여백 24px (ml-6)
- depth 2: 왼쪽 여백 48px (ml-12)

## 키보드 단축키 (수정 모드에서만 동작)

### E 또는 e키

- 현재 선택된 투두의 텍스트 편집 모드 진입
- 편집 중이 아닐 때만 동작

### Enter키

- 편집 중: 편집 완료 및 저장
- 편집 중이 아님: 새 투두 추가 (현재 선택된 투두 다음 위치)

### Tab키

- Depth 증가 (최대 depth 2까지)
- 바로 위 투두가 부모가 될 수 있을 때만 동작

### Shift + Tab키

- Depth 감소 (최소 depth 0까지)

## Order 관리 상세

### 초기 Order 설정

- 새로운 투두 목록은 10씩 간격을 두고 order 할당 (0, 10, 20...)
- 중간 삽입을 위한 여유 공간 확보

### 새 투두 추가 시 Order 계산

- 맨 끝에 추가: 마지막 order + 10
- 중간에 삽입: 앞뒤 투두의 order 평균값
- 예: order 10과 20 사이 삽입 시 15

### 드래그앤드롭 시 Order 재계산

- 이동된 위치의 앞뒤 order 값의 평균 계산
- 자식 항목들은 부모 바로 다음에 연속적으로 재배치

### Order 정규화

- 저장 시 전체 투두를 order 순으로 정렬
- 10씩 간격을 두고 재할당 (소수점 제거)

## 드래그앤드롭 세부 규칙

### 이동 제약사항

1. 같은 depth 레벨 간에만 이동 가능
2. depth 0 항목은 depth 0 위치로만 이동
3. depth 1, 2 항목은 같은 부모 아래에서만 이동

### 부모-자식 관계 유지

- 부모 투두 이동 시 모든 자식 투두도 함께 이동
- 자식들의 상대적 순서는 유지
- 자식들의 order는 부모 바로 다음부터 순차적으로 재배치

### 드래그 가능 영역

- 드래그 핸들(세로 점 6개)을 통해서만 드래그 시작
- 텍스트나 체크박스 영역은 드래그 불가

## 가져오기 기능 상세

### 버튼 상태

- 0개 선택: 버튼 비활성화, 회색 배경
- 1개 이상 선택: 버튼 활성화, 흰색 배경

### 가져오기 동작

1. 선택된 어제 투두들을 복사 (원본 유지)
2. 오늘 투두 목록 끝에 추가
3. 새로운 ID 생성 및 date를 오늘로 변경
4. order는 기존 오늘 투두들 다음부터 할당
5. depth와 부모-자식 관계 유지

### 가져오기 후 처리

- 선택 상태 초기화
- 가져온 항목 개수 피드백 (토스트 메시지 등)

## UI/UX 세부사항

### 색상 가이드

- 기본 버튼: 흰색 배경, 회색 테두리
- 비활성 버튼: 회색 배경, 회색 텍스트
- 선택된 체크박스: 보라색 (purple-600)
- 완료된 투두: 회색 텍스트, 취소선
- 편집 중인 투두: 노란색 배경 (yellow-50)

### 호버 효과

- 투두 항목: 회색 배경 (gray-50)
- 버튼: 약간 어두운 배경
- 드래그 핸들: 진한 회색으로 변경

### 반응형 디자인

- 최대 너비 4xl (896px)
- 모바일에서는 드래그 핸들 크기 증가
- 패딩과 간격 조정

## 유효성 검증

### 텍스트 입력

- 최소 1자 이상 (공백 제거 후)
- 최대 500자 제한
- 특수문자 허용

### Depth 변경

- 증가: 바로 위 투두의 depth가 현재보다 크거나 같을 때만
- 감소: depth가 1 이상일 때만
- 자식이 있는 경우 함께 조정

### 드래그앤드롭

- 유효한 드롭 위치인지 검증
- 자기 자신이나 자식 위치로는 이동 불가

## 성능 최적화 고려사항

### 메모이제이션

- 정렬된 투두 목록 캐싱
- 복잡한 계산 결과 재사용
- 콜백 함수 메모이제이션

### 가상화

- 투두가 100개 이상일 경우 가상 스크롤 적용
- 화면에 보이는 항목만 렌더링

### 디바운싱

- 텍스트 입력 시 300ms 디바운싱
- 자동 저장 기능 구현 시 활용

## 접근성 고려사항

### ARIA 레이블

- 체크박스: "투두 완료 상태 변경"
- 드래그 핸들: "투두 순서 변경을 위한 드래그 핸들"
- 편집 입력 필드: "투두 텍스트 편집"

### 키보드 네비게이션

- Tab키로 모든 인터랙티브 요소 접근 가능
- Space바로 체크박스 토글
- 화살표 키로 투두 간 이동 (선택 기능)

### 스크린 리더 지원

- 상태 변경 시 알림
- 모드 전환 시 안내
- 드래그앤드롭 대체 수단 제공
