# 📋 PRD (Product Requirements Document)

## 1\. 제품 개요

### 1.1 제품명

**Scrumble**

### 1.2 제품 비전

"AI 시대에 잃어가는 인간적 연결을 업무 환경에서 되찾자"

- 단순 업무 공유를 넘어 팀원 간 감정적 유대와 상호 지지를 형성하는 플랫폼

### 1.3 핵심 가치

1. **Human Connection**: 사람 중심의 따뜻한 소통
2. **Seamless Experience**: 부담 없이 매일 사용할 수 있는 직관적 UX
3. **Team Wellness**: 팀의 정서적 건강도 향상

### 1.4 타겟 사용자

- **Primary**: 5-15명 규모의 스타트업 개발/디자인/마케팅 팀
- **Secondary**: 원격/하이브리드 근무 환경의 프로젝트 팀
- **특성**: 20-40대, 수평적 문화, 빠른 커뮤니케이션 선호

## 2\. 사용자 스토리 & 시나리오

### 2.1 핵심 사용자 플로우

#### 아침 체크인 (8:30 AM)

```markdown
1. 모바일에서 Scrumble 접속
2. "오늘의 컨디션" 슬라이더로 7점 선택
3. "커피 없이는 못 살겠어요 ☕" 한 줄 입력
4. 체크인 완료 → 팀 피드로 자동 이동
5. 팀장의 체크인에 "힘내요!" 이모지 리액션\*0
```

#### 점심시간 인터랙션 (12:30 PM)

```markdown
1. 동료의 낮은 컨디션 점수(3점) 확인
2. "점심 같이 먹어요!" 댓글 작성
3. 실시간으로 "고마워요 ❤️" 답글 확인
```

### 2.2 페르소나

**김개발 (28세, 주니어 개발자)**

- Pain Point: 원격 근무로 팀원들과 소통 부족
- Need: 캐주얼한 일상 공유와 정서적 교감

**고예술 (30세, 시니어 디자이너)**

- Pain Point: 개발 팀에 디자인 혼자라 팀원간 커뮤니케이션 부재
- Need: 개발자들의 업무 팔로업과 그들과 가까워지고 싶음

**조팀장 (35세, 개발팀 리드)**

- Pain Point: 팀원들의 컨디션 파악 어려움
- Need: 팀 분위기를 한눈에 파악하고 케어, 조직 내 심리적 안정감 구축

## 3\. 기능 요구사항

### 3.1 MVP (Phase 1) - 1-2주 개발

#### 3.1.1 인증 시스템

- 구글 OAuth 로그인 (goth 라이브러리)
- JWT 기반 세션 관리
- 프로필 설정 (이름, 프로필 사진)

#### 3.1.2 워크스페이스

- 워크스페이스 생성/삭제
- 초대 링크 생성 및 가입
- 멤버 목록 조회
- 관리자 권한 (멤버 삭제)

#### 3.1.3 체크인 핵심 기능

- **체크인 작성**
  - 컨디션 점수 (1-10 슬라이더)
  - 오늘의 한마디 (글자 수 제한 없음)
  - 작성 시간 자동 기록
- **팀 피드**
  - 오늘 체크인한 멤버 카드형 표시
  - 체크인 시간순 정렬
  - 미체크인 멤버 흐릿하게 표시
- **이모지 리액션**
  - 6개 기본 이모지 (❤️ 👍 🔥 💪 🤗 ☕)
  - 클릭 시 즉각 애니메이션
  - 리액션 카운트 표시

#### 3.1.4 모바일 최적화

- 반응형 디자인 (Mobile First)
- PWA 설정 (홈 화면 추가)
- 터치 친화적 UI (최소 44px 터치 영역)
- But, PC 웹 화면도 중요

### 3.2 Phase 2 (3주차)

#### 3.2.1 투두 시스템

- 투두 추가/수정/삭제
- 체크박스로 완료 처리
- 전날 미완료 투두 가져오기

#### 3.2.2 실시간 댓글

- 텍스트 댓글 작성
- WebSocket 실시간 동기화
- 댓글 알림 (빨간 점)

#### 3.2.3 체크아웃

- 투두 완료 상태 확인
- 간단한 회고 작성
- 하루 요약 자동 생성

### 3.3 Phase 3 (4주차 이후)

#### 3.3.1 AI 기능

- 회고 질문 자동 생성
- 팀 무드 인사이트
- 주간 리포트 생성

#### 3.3.2 통계 대시보드

- 개인/팀 무드 트렌드
- 체크인 스트릭
- 인터랙션 히트맵

## 4\. 기술 명세

### 4.1 백엔드 아키텍처

```diff
- Framework: Fiber v2 (Golang)
- Database: PostgreSQL + EntGo ORM / atlas
- Cache: Redis (실시간 상태)
- WebSocket: Fiber Websocket
- Auth: goth (Google OAuth)
- Logging: Zap
```

### 4.2 프론트엔드 스택

```diff
- Framework: Next.js 14 (App Router)
- Language: TypeScript
- Styling: Tailwind CSS
- State: Zustand
- API: Axios + React Query
- Animation: Framer Motion
- PWA: next-pwa
```

### 4.3 인프라 구성 (프로덕션 예상)

```diff
- Backend: Railway ($20/월)
- Database: Supabase ($25/월)
- Frontend: Vercel (무료)
- Storage: Cloudflare R2
- Monitoring: Sentry (무료 티어)
```

### 4.4 API 설계 원칙

- RESTful API + WebSocket for 실시간
- JWT Bearer 인증
- 에러 코드 표준화
- Rate Limiting (100 req/min)

## 5\. 비기능 요구사항

### 5.1 성능

- 체크인 작성: < 1초
- 피드 로딩: < 2초
- 이모지 리액션: < 100ms

### 5.2 보안

- HTTPS 필수
- SQL Injection 방지 (EntGo)
- XSS 방지 (React 기본)
- CORS 설정

### 5.3 확장성

- 100개 팀, 1,500명 동시 사용
- 일일 10,000 체크인 처리
- 멀티 테넌시 지원

## 6\. UI/UX 가이드라인

### 6.1 디자인 원칙

- **Warm & Friendly**: 따뜻한 색상과 둥근 모서리
- **Micro-interactions**: 모든 액션에 즉각적 피드백
- **Mobile First**: 엄지 하나로 조작 가능

### 6.2 주요 화면

1. **체크인 화면**: 큰 슬라이더 + 텍스트 입력
2. **팀 피드**: 카드형 레이아웃 + 플로팅 리액션
3. **프로필**: 개인 통계 + 설정

## 7\. 개발 로드맵

### 7.1 스프린트 계획

- **Sprint 1 (1주)**: 인증 + 워크스페이스 + 체크인 + 피드 + 이모지 + 모바일
- **Sprint 2 (1주)**: 테스트 + 배포

### 7.2 작업 분배

- Main 풀스택 개발자: 인증, 체크인, 댓글 기능
  - Sub 개발자: 메인 개발자가 만든 조직 생성 기본에 조직 관리 정책 구현
- Main 디자이너
  - 기본 와이어프레임, 스타일링, 애니메이션
- **AI Agent**: 테스트 코드 + 문서화

## 8\. 성공 지표

### 8.1 단기 (1개월)

- 10개 팀 가입
- 일일 체크인율 70%
- 팀당 일일 리액션 20개

### 8.2 중기 (3개월)

- 50개 팀 사용
- 주간 리텐션 60%
- NPS 40 이상
